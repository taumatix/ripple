# Changelog

All notable changes are listed here. The format follows Keep a Changelog; versions follow SemVer.

## [Unreleased]

### Fixed

- A verified build no longer leaves a binary in the PR: for a repository whose only package is `package main`, the verification `go build ./...` wrote the executable into the checkout and the next `git add -A` committed it. The build now discards its output (`-o` the null device). Verified by an end-to-end test against the fake host and by the image smoke test, which now uses a main-only repository.

- Flaky tests fixed (ROADMAP 256, 197): `App.Tick` and its housekeeping now go through the app's start-up `sync.Once` before reading the queue, so calling `Tick` while `Run` is starting no longer races (a data race only tests and cron can reach; no behaviour change otherwise); `Reap` looks again, at most four more times half a second apart, when its first `kill` and `rm -f` both find no container, so a container the runtime creates just after a short timeout killed its client is no longer left running. The two postgres e2e tests wait on the condition they assert and no longer swap `Engine.Store` under a running app; the Apple `container` reap test polls like the shared check. Covered by `-race` stress runs; the late-container case is covered by a fake runtime, and whether it was the cause of the one CI failure of `container-runtimes (docker)` is not proven (no log can tell).

### Added

- Maven (opt-in `ecosystem: maven` only; nothing outside it changes): a two-segment version (`4.13`) is now read and moved, to a two- or three-segment release (a three-segment declaration still moves to three-segment releases only), and a version given as `${x.version}` is read from the pom's own `<properties>` and moves by editing the property's value, when the property is declared once and every use is a dependency version of one `groupId:artifactId`; otherwise it is left alone. Parents, BOMs, a property shared by several artifacts and command-line overrides are not handled ([docs/maven.md](docs/maven.md), ROADMAP 239). Covered by unit tests from the vendored POM reference, an end-to-end run against the fake Central, and `TestRealtoolMaven` (CI; `mvn` was not available where this was written, so that run is untested locally).

- Terraform (opt-in): a two-segment pessimistic constraint (`~> 1.2`) is now read and keeps its shape when moved (`~> 1.5` for release 1.5.3), per HashiCorp's version-constraints page. Floors and ranges (`>= 1.0`, `< 2.0`) stay unread on purpose (ROADMAP 250). Verified by unit and end-to-end tests against the fake registry; the realtool check (`terraform init` on the edited fixture) has not been run locally, only in CI.

- GitHub (github.com and GHES) head polling: a repository whose default-branch head moved is re-scanned at the next discovery even if its push webhook never arrived. One GraphQL request reads 100 repositories' heads, the whole read is kept for `Client.HeadEvery` (default 10 minutes), and a 429, secondary limit or low `rateLimit.remaining` ends the round and is retried later (see `docs/platform-github-enterprise.md`). Additive: `app.InstalledHeadLister`, `platform.RepoHead`, `github.AppAuth.Installations`, `github.Client.HeadEvery`. Verified against the fake GitHub and GHES only; not run against a real GitHub or GHES, and the `RATE_LIMITED` error type, the minimum query cost of 1 and the null `defaultBranchRef` of an empty repository are assumed. A live test cannot cover it (GraphQL needs a token).

- Bundler (opt-in `ecosystem: bundler`): a two-segment `gem "x", "~> 1.2"` is now read; a release of a later major moves it to the release's first two segments (`~> 2.1`) as a `major` update, a later release of the same major is not proposed (the constraint allows it already). Gemfiles with such a gem were left alone before. `>=`/`>` floors stay unread (they already allow every later release). Verified against the fake rubygems.org, the Gemfile man page text (docs/vendor/rubygems/gemfile.md) and `bundle lock` (`TestRealtoolBundlerTwoSegment`); not run against a real repository's Gemfile.

- Composer (opt-in `ecosystem: composer`): a two-segment `"^1.2"`, `"~1.2"` or `"^0.3"` is now read. Only a release outside the constraint's line moves it (a later major, or for `^0.Y` a later minor), to the release's first two segments (`^2.4`); a later release of the same line is not proposed because the constraint allows it already. `||` alternatives, `~0.Y`, `^1` and `~1` stay unread. Verified against the fake Packagist and the vendored Composer versions article; not run against a real repository's composer.json (php and composer were not installed where this was written; the `realtool` composer job covers only the existing three-segment form).

- With `RIPPLE_POLL_PACKAGES_PER_POLL` set, a package poll reads only its slice of the polled-package set through the store's optional paged cursor listing instead of listing the whole set; the packages visited and their rotation are unchanged, and the legacy cursor, stores that do not page, and the unset default keep the whole read.

- Gerrit, SCM-Manager and CodeCommit implement `app.HeadLister`: a listed repository whose default-branch head moved is re-scanned at the next discovery even if its webhook or event never arrived. Costs one to two extra reads per repository per discovery (see each `docs/platform-*.md`); verified against the fakes only.

- Head polling (Gerrit, CodeCommit) catches a head that moved while ripple was down on the first discovery after a start instead of the second: the default branch each host reports is used in the same round, and CodeCommit reads unknown default branches 100 at a time with `BatchGetRepositories`. Verified against the fakes only.

- GitLab implements `app.HeadLister`: a member project whose default-branch head moved is re-scanned at the next discovery even if its push webhook never arrived, at one extra read per project per discovery (see `docs/platform-gitlab.md`); verified against the fake only. The other webhook hosts are still push-only.

- `RIPPLE_SANDBOX=bwrap` now works: `go` runs in a network namespace whose only route out is an in-sandbox relay (`ripple sandbox-relay`, an internal subcommand) to the module proxy gate, served additionally on a private unix socket, and fails closed when it cannot be set up. Verified under real bubblewrap in the `sandbox-bwrap` CI job (a skipped sandbox test fails it); see `docs/sandbox.md` for what is not covered.

- Bundler (opt-in `ecosystem: bundler` only; a `Gemfile` outside it is never read): a one-segment `gem "x", "~> 1"` is now read. Real `bundle lock` resolves it inside 1.x (same as `~> 1.0`), so only a release of a later major moves it, to that release's major alone (`~> 2`). Verified by `TestRealtoolBundlerOneSegment` against real bundler (CI `realtool / bundler`) and by the fake-host e2e test; `~> 0` is read the same way and is covered by the unit and engine tests only.

- Composer (opt-in `ecosystem: composer` only; a `composer.json` outside it is never read): `"~0.3"` and the one-segment `"^1"`, `"~1"` and `"^0"` are now read. Real Composer 2 locks `~0.3` to mockery 0.9.11 and `^1`/`~1` to monolog 1.27.1, so only a release of a later major moves them, written as its first two segments (`~1.2`) or its major alone (`^2`). Verified by `TestRealtoolComposerConstraintMeaning` against real composer (CI `realtool / composer`) and by the fake-host e2e test.

- NuGet (opt-in `ecosystem: nuget` only; a project file outside it is never read): a `PackageReference`'s `<Version>` child element, and a `PackageReference Update="Id"` that follows an `Include="Id"` in the same file, are now read and their version digits edited. Real `dotnet restore` resolved each form (`TestRealtoolNugetItemForms`, CI `realtool / nuget`) and the fake-host e2e test drives the PRs. Where dotnet uses another item than the one first written, ripple follows it: an Include that a later Update overrides is skipped (the Update is edited, no PR for the dead Include), and an Include with both a `Version` attribute and a `<Version>` child is edited at the child. Edits are round-tripped through real `dotnet restore` (`TestRealtoolNugetItemFormsEdit`). Not read yet, and listed in `docs/nuget.md`: an Update in another file, `PackageVersion Update=`, `VersionOverride=`.

- Gitea and Forgejo now run for real in CI (`hosts-gitea.yml`: Gitea 1.27.3, Forgejo 17.0.2, Forgejo 7.0.16 as containers), the full conformance suite plus `TestReal*`, with the answers in `docs/vendor/gitea/real-answers.md`. NOT verified: Forgejo before 7, Gitea before 1.27, PostgreSQL or MySQL back ends, the 429 of a real throttling proxy (no instance throttles; the 429 is injected), a person's label, comment or rename read as a touch, a scheduled merge actually merging, repository deleted and renamed webhook actions (a delete is never announced), and archive. A repository whose first push races a discovery used to stay unregistered until the next one; the Gitea and Forgejo listing now waits for it (`Client.EmptySettle`, default 5 s, once per repository), proved on the real instances with a fixture that no longer waits. NOT covered: a `repository` created webhook for a still-empty repository (ROADMAP 283). SCM-Manager is not yet run for real (ROADMAP 18).

- bwrap now runs for real on `ubuntu-22.04` (bubblewrap 0.6.x) as well as 24.04 and latest, and a cgo build runs under it in CI (`TestCgoBuildUnderBwrap`). The relay stays without a byte limit, with the reasoning and an 80 MiB transfer test in `docs/sandbox.md` (ROADMAP 1)

## [0.4.0] - 2026-11-25

Additive release: no public API was removed or changed. Opt-in ecosystems: Helm, Bundler, Composer, NuGet, Maven and Terraform
(`ecosystem:`), each verified against a fake registry, the real public registry (`-tags live`) and the ecosystem's own tool
(`-tags realtool`) in CI. Not verified: private registries and authenticated paths, lock-file regeneration, GitLab, Gitea,
Bitbucket, Data Center, GHES and real DynamoDB behaviour.

Behaviour that changes **without** an opt-in, for existing deployments:
- pip and Cargo propose the newest older release the repo's Python or compiler can use instead of only skipping a release
  that its `Requires-Python` or `rust-version` excludes.
- Docker tag parsing reads zero-padded tags such as `22.04`.
- A Cargo requirement is now read with a byte-offset TOML scanner, so more manifests are read and more requirements move.

### Added
- Real-tool tests: registry-reaching steps retry (3 attempts) and report the tool's own error when exhausted, the Maven test names the dependency plugin by full coordinates, and the Cargo, Composer, NuGet and Maven jobs cache their downloads. Test and CI only.
- Real-tool tests (`-tags realtool`, [docs/realtool.md](docs/realtool.md), `.github/workflows/realtool.yml`): a small real Go, Cargo, npm, pip, Helm, Bundler, Composer, NuGet, Maven, Terraform, GitHub Actions and Docker project is edited by the manager and then checked by the ecosystem's own tool. Test and CI only; no behaviour change.
- Live tests (`go test -tags live`, [docs/live-tests.md](docs/live-tests.md)) for the RubyGems, Packagist, NuGet, Maven Central, Terraform registry and Helm repository datasources, run through the production clients against the real public endpoints; the `live` workflow now runs daily and on pull requests that touch a datasource package, and `internal/livetest` also retries a transient 500, 502 or 504.
- Composer: `ecosystem: composer` (opt-in, [docs/composer.md](docs/composer.md)) bumps the `require` and `require-dev` versions (`1.2.3`, `^1.2.3`, `~1.2.3`) of a `composer.json` against Packagist (new `internal/packagist` datasource `packagist`, `manager.Composer`, `engine.PackagistWatcher`, additive). Offset-keeping edit; `composer.lock` reported stale; a file with any `repositories` entry is left alone. Covered against a fake Packagist only, nothing verified against the real one.
- NuGet: `ecosystem: nuget` (opt-in, [docs/nuget.md](docs/nuget.md)) bumps the `Version` of `PackageReference` and `PackageVersion` items (`1.2.3`) in `*.csproj`, `*.fsproj`, `*.vbproj` and `Directory.Packages.props` against nuget.org's flat container (new `internal/nuget` datasource `nuget`, `manager.Nuget`, `engine.NugetWatcher`, additive). Offset-keeping edit; `packages.lock.json` reported stale; ranges, floating versions, properties and prereleases are left alone; `NuGet.Config` private feeds are not read (documented dependency-confusion caveat). Verified against a fake registry only, not the real nuget.org.
- Terraform: `ecosystem: terraform` (opt-in, [docs/terraform.md](docs/terraform.md)) bumps the registry module and provider versions (`1.2.3`, `= 1.2.3`, `~> 1.2.3`) in `*.tf` files against the Terraform registry's `/v1/modules/.../versions` and `/v1/providers/.../versions` (new `internal/terraform` datasource `terraform`, packages `modules/ns/name/provider` and `providers/ns/type`, `manager.Terraform`, `engine.TerraformWatcher`, additive). Offset-keeping edit; ranges, other operators, interpolated values, hosted, git and local sources are left alone, and `.terraform.lock.hcl` is reported stale in provider PRs, not rewritten. Verified against a fake registry only, not the real one.
- Maven: `ecosystem: maven` (opt-in, [docs/maven.md](docs/maven.md)) bumps the literal `<dependency>` versions (`1.2.3`) of a `pom.xml` against Maven Central's `maven-metadata.xml` (new `internal/maven` datasource `maven`, package `groupId:artifactId`, `manager.Maven`, `engine.MavenWatcher`, additive). Offset-keeping edit; property-indirected versions, ranges, qualified and one- or two-segment versions are left alone, as is any pom that declares `<repositories>`. Verified against a fake repository only, not the real Maven Central.
- Bundler: `ecosystem: bundler` (opt-in, [docs/bundler.md](docs/bundler.md)) bumps the `gem "name", "1.2.3"` / `"~> 1.2.3"` versions of a `Gemfile` against rubygems.org (new `internal/rubygems` datasource `rubygems`, `manager.Bundler`, `engine.RubygemsWatcher`, additive). Offset-keeping edit; `Gemfile.lock` reported stale; git, path and non-rubygems.org sources left alone. Covered against a fake rubygems.org only, nothing verified against the real one.
- `platform.PR.Body`, filled by the PR read of GitHub, GitLab, Gitea and Forgejo, Azure DevOps, Bitbucket Cloud and Server and CodeCommit (empty on Gerrit). A superseded-PR sweep now leaves a PR alone when its head commit or description differs from what ripple recorded when it opened it, which catches edits the host's own feeds cannot show; jobs with nothing recorded are never treated as edited (ROADMAP 94, new 229).

### Fixed
- Supersede: a rerun of the lower job, whose recorded PR is cleared, no longer strands its PR beside a higher one: the open PRs are judged again after a job re-finds its PR already open (ROADMAP 179, new 225).

### Added
- Helm: `ecosystem: helm` (opt-in, [docs/helm.md](docs/helm.md)) bumps `Chart.yaml` / `requirements.yaml` dependencies against a chart repository's `index.yaml` (new `internal/helmrepo` datasource `helm`, `manager.Helm`, `engine.HelmWatcher`, additive). No store interface changed. Nothing reads them yet: the comparison is ROADMAP 228 (first half of 94). Covered end to end over the fake GitHub on the memory store and the DynamoDB fake; the Postgres migration and queries run through the shared store suite in CI only.

The latency is the HTTP acknowledgement, not event processing (new residual).
- pip: a `setup.cfg`'s `[options] python_requires` now feeds the Requires-Python guard (after `pyproject.toml`, before `Pipfile`, in the same directory); `manager.PipPythonFiles` gains `setup.cfg` (additive; ROADMAP 218).

The image smoke test now serves the fake module from a proxy with it set to `off` and asserts the bumped `go.mod` and `go.sum` (ROADMAP 3; the image run itself is CI-only, the binary run was done locally).
- `security-bypass-limit-per-advisory: N` on a `gomod` update entry (default 0, no cap; `config.Update.SecurityBypassLimitPerAdvisory`, additive) caps how many open PRs one advisory may bypass the open pull request limit with; the rest wait for a slot. Covered end to end against the fake GitHub and fake OSV (ROADMAP 212, new 226).
- pip: when the Requires-Python guard skips a release, ripple queues a job for the newest older release the repo's Python can run (if it is still an update for the dependency and the repo's rules allow it); the skip reason says "retargeted to X". Not opt-in: it only replaces a skip with an ordinary update. New `pypi.Project.NewestRelease` (additive). Fake GitHub and fake PyPI only (ROADMAP 217).
- Docker: an ingress-nginx style Helm values block (`registry:`, `image: path/name`, `tag:` under `image:`, no `repository:`) is read like a `repository:`/`tag:` pair, and a zero-padded second or third tag number (`ubuntu:22.04`) is a tracked tag (`registry.ParseTag`; a tag like `22.04` was untracked and now moves, so this is a behaviour change for such images). Fake registry and fake GitHub only (ROADMAP 219).
- Cargo: when a release's `rust_version` is newer than the repo's `rust-version`, the newest older release the repo's compiler can build is proposed instead of only skipping (job reason says `retargeted to X`). Opt-in is not needed: it replaces a skip with an ordinary update. Covered end to end against the fake crates index; real crates.io unverified (ROADMAP 156).
- `app.HeadLister` (optional, additive: `ListRepoHeads(ctx) map[repo]sha`) on a `platform.Lister` host: `App.Discover` remembers each listed repo's default-branch head per repo (`discover-head/<host>#<repo>`) and queues a whole-repo Push when it moved, so a host with no push webhooks is re-scanned. Covered end to end on the memory store through the queue (the processed push re-uses the existing push path). No host implements `HeadLister` yet: that belongs in the platform packages (ROADMAP 221).\n- GitLab: a push authenticated by the plain secret token (no signing key) is parsed as it streams, like a signed one, instead of being read whole first (`webhook.Guard.ReadStream`, additive; ROADMAP 205).

No API change. Covered end to end on the DynamoDB fake with a 15000-repo listing (red against the single cursor) and on the memory store for the move; Postgres runs the same code through the shared store suite in CI only.

### Fixed
- Feed poll: a poll no longer waits for a repo a job is running. The poll ends by syncing dashboards, which took each marked repo's in-process lock, so a poll that enqueued a job for a repo whose run began before the sync (a slow checkout) stalled, and every later poll with it, until that job ended; the repo is now skipped and stays marked for the next flush, as a repo another replica holds already was. Showed up as an intermittent `TestSlowJobDoesNotStallFeedPoll/dynamodb` timeout in CI. Verified by an engine test; the DynamoDB Local run is CI-only.
- A failed event's retry could lose its lease to the previous attempt's release: the queue made the event runnable again before releasing its lease, the retry re-took the same owner's lease with the same token, and the late release deleted it, so the retry's outcome was refused as lost, its attempt not counted, and the event rescanned more than `MaxAttempts` times (seen as `TestDeadLetterThenRequeue/postgres`: 5 scans, want 3). The lease is now released before the event is queued again. Reproduced on the memory store with a slow release; the Postgres run is CI-only.
- Container backends: a command that timed out left its container behind, stopped, about half the time under Apple's CLI (`--rm` is the killed client's job); the reaper now always removes it. The live test checks only its own container and reports debris from other runs.
- CI: the `test` job piped `go test` into `tee` without `pipefail`, so failing tests never turned it red; it now runs with `set -o pipefail`. Data race fixed: a webhook delivery read `Queue.Now` (`App.nowTime`, from `claimDelivery`) while `Queue.Run` filled in the queue defaults; `nowTime` now goes through the idempotent, mutex-guarded `Queue.init`. Regression test `TestDeliveryWhileQueueStartsDoesNotRace`.

### Security
- OS-level sandbox for `go` and local `git` (`RIPPLE_SANDBOX`: `none` (default), `auto`, `seatbelt`, `bwrap`).
  Under `seatbelt` (macOS) the commands run with every path unreadable and unwritable except the
  checkout, the build cache and the toolchain, and the only network they can open is a loopback gate
  to `RIPPLE_GOPROXY` behind a random path prefix. `bwrap` (Linux) puts them in a network namespace whose
  only route out is an in-sandbox relay to the same gate, and refuses to run otherwise. Clone, fetch and push are not
  confined. See [docs/sandbox.md](docs/sandbox.md).
- Webhook receiver: requests without a well-formed `X-Hub-Signature-256` are refused before the body is
  read, at most 4 bodies are buffered at once (others get 503 with `Retry-After`), and a declared length
  over the limit gets 413. A repeated `X-GitHub-Delivery` within an hour is acknowledged and dropped, so a
  replayed signed event is handled once; a delivery that failed with 503 can still be redelivered.
  `webhook.Handler` gains optional `MaxBody`, `MaxInflight`, `DedupeTTL` and `Now` fields; zero values keep safe defaults.

  docs/bounds.md).
- Fan-out loads and parses a repo's config once per release instead of once per dependency row.

- `.github/ripple.yml`, the path v0.1.0 read, is a deprecated alias for `.ripple.yaml` with identical
  meaning. When both exist `.ripple.yaml` wins, the alias is ignored, and a warning is logged and shown
  by `ripple config validate`. Removal no earlier than v0.3.0.

### Documentation
- ROADMAP entries for every Renovate code host, container job runners with updaters as OCI images,
  a prebuilt image and binaries, and hermetic integration tests.

## [0.1.0] - 2026-11-22

### Added
- `ripple version` prints the module version the binary was built from.
- Event-driven updater: polls the Go module index once, finds importing repositories through a
  reverse index, and opens pull requests only there.
- `.github/ripple.yml` per-repo configuration with strict validation; `ripple config validate`.
- Managers: `gomod` and a generic `regex` manager.
- Stores: Postgres and DynamoDB (single table, documented GSI), plus an in-memory store.
- minimumReleaseAge, grouping, per-rule automerge, schedule windows and an open-PR limit.
- GitHub App webhook receiver and `ripple serve`; Dockerfile.
- Go major-version updates: the reverse index keys on the module line, so `/vN` to `/vN+1`, an
  unsuffixed path to `/v2` and `gopkg.in/x.v2` to `.v3` are found; `go.mod` and all import paths are
  rewritten with `go/parser`, verified with `go mod tidy`, `go build` and `go vet`, opened as a
  labelled `[major]` PR (a draft with the compiler output if verification fails), never auto-merged
  unless the repo file says `automerge: major`. New server setting `RIPPLE_GOPROXY`.

### Security
- `go` is no longer run in a checkout containing a symlinked `go.mod`, `go.sum`, `go.work` or `.go`
  file, or a `replace` to an absolute or out-of-repository path; the job fails permanently, no PR.

### Fixed
- The regex manager replaced only some matches when several patterns matched out of offset order;
  matches are now sorted, and overlapping ones are rejected.
- A major bump no longer fails because one `.go` file does not parse (it is listed in the PR body),
  and no longer rewrites `testdata/` or directories starting with `_` or `.`.
- Corrected the `webhook.Sink` comment: GitHub does not redeliver a failed webhook by itself.

### Documentation
- README section "Known limitations and security model"; ROADMAP entries for an OS sandbox,
  durable per-installation queues, scan bounds, webhook body bounds, per-command tokens and delivery dedupe.
