# Changelog

All notable changes are listed here. The format follows Keep a Changelog; versions follow SemVer.

## [Unreleased]

### Added
- Supersede: a stale PR a person touched is remembered with its head commit (`platform.PR.HeadSHA`, new and additive; read from the GitHub, GitLab and Gitea/Forgejo open-PR listings), and when the head moves the host is asked again, so a person who takes their edit back (a reset to ripple's own commit) no longer keeps the PR open until it closes (ROADMAP 124). Hosts that report no head keep the old behaviour; an old cursor reads as head unknown. Covered end to end against the fake GitHub only; the GitLab and Gitea parsing follows their documented `sha` / `head.sha` fields and no test or real host exercised it (ROADMAP 177).
- Archive on listing hosts: GitLab, Gitea/Forgejo and Bitbucket Data Center (8.0+) send no archive event, so discovery now also lists the archived repos (`platform.ArchivedLister`, new and optional) and a repo that moves between the two listings is paused or resumed instead of removed or added: its index and pending jobs are kept (ROADMAP 107). Before, an archived project was forgotten with its jobs. Seen within one discovery interval. Covered by the conformance suite (`ReportsArchives`) against each host's fake and an app unit test; shapes from the vendored GitLab and Data Center docs; nothing ran against a real host. Bitbucket Cloud and Azure DevOps document no archive (ROADMAP 176, 175).
- Webhooks: `installation` and `installation_repositories` deliveries now carry each added repository's id (`webhook.Event.RepoIDs`, `platform.Event.RepoIDs`, both new and additive), and a repo registered that way stores it, so its first rename is followed by id without waiting for a signed push (ROADMAP 109). Shape from the vendored octokit schemas in `docs/vendor/github`; covered end to end against the fake GitHub; no real GitHub delivery was seen. A push with a mismatched id is still ignored (ROADMAP 173).
- CI: an `e2e-repeat` job runs `internal/e2e` with `-race -count=2` against the same Postgres and DynamoDB Local services, so a test that depends on run order or leftover state fails (ROADMAP 146). Run locally without the services (which skip) it passed twice; the service-backed second pass is CI-only.
- DynamoDB: `RIPPLE_DYNAMODB_SCAN_PAGE` and `RIPPLE_DYNAMODB_SCAN_PAUSE_MS` page and rate-limit the whole-table Scans of `ripple dynamodb check-counts`, `recount` and `backfill-failed-jobs`, and `RIPPLE_DYNAMODB_DRIFT_CHECK_INTERVAL` has the server compare the dependents counters with their index periodically and log the gap (read only). `store.WithScanPaging` and `app.App.DriftCheckEvery` are new (additive); all default off. Covered against the in-process fake end to end (config to store to log line) and by unit tests that the pause is kept and a cancelled context ends it; the size of a Scan on a large real table was not measured and nothing ran against real AWS (ROADMAP 176).
- Container sandboxes: `RIPPLE_CONTAINER_GO_IMAGES` (`1.26=ripple-runner:1.26,...`) names an image per Go minor; `go mod`, `build` and `vet` for a go.mod naming a configured minor (its `toolchain` line, else its `go` line) run in that image, so a directive bump above the default image's Go is checked by the Go it asks for instead of opening a draft, and the PR body names the image. `sandbox.Policy.Image`, `platform.GoVerify.Image`, `platform.GoMinor` and `engine.Engine.GoImages` are new (additive); `make runner-images` builds the images. Covered end to end against the fake runtime (argv and PR body); CI builds each minor and runs `go version` in it; no real runtime has run a verification in a per-minor image. Toolchain downloads are not added (ROADMAP 171).
- OSV: `security-bypass: [open-pull-requests-limit, schedule]` on a `gomod` update entry lets a security PR open at the repo's PR cap and outside its schedule. Off by default, so nothing changes unless a repo asks.
- Directives (`directives: extended`): mockgen's `-self_package` import path moves with the module it names, and the `github.com/golang/mock` flags `-exec_only`, `-prog_only` and `-version` are read, so those lines are rewritten instead of left whole. `stringer` takes no import path (its flag set is vendored under `docs/vendor/stringer`), so there is nothing to rewrite. Additive. Covered by directive unit tests and the major-bump end-to-end test against the fake GitHub; no real mockgen or stringer was run on a rewritten line (ROADMAP 170).
- Backfill lookup: the module proxy lookup falls back to the version list for a prerelease-only module, skips a latest that its own go.mod retracts for the newest stable (then prerelease) version that is not retracted, and caches answers, unknown modules included, for ten minutes so a module new to many repos is asked once (`feed.GoProxyLookup.Now` is new, additive). Covered end to end against the fake proxy and by unit tests, and spot-checked read-only against proxy.golang.org; no retracted real module was tried. A module that skipped more than three majors is still found only by the feed (ROADMAP 169).
- OSV: a corrected record now finds a pending job made before the `osv-jobs` index existed. The watcher indexes the repos' open jobs once after an upgrade (`osv-jobs-backfill` cursor, `SweepBatch` repos per poll).
- Queue: a queued rename or default-branch event that carries only the deprecated overloaded `Ref` is logged at WARN when handled (`queued event has no typed field; using the deprecated Ref`), so the overload's removal (ROADMAP 76) can be judged from a deployment's logs.
- Webhooks: a GitHub delivery's body is parsed as it streams in (`webhook.Guard.ReadVerifiedStream`, an internal token-level extractor that keeps only the fields ripple acts on), so a signed body of any size is no longer held on disk or in memory; a forged body's parse is discarded with the 401. Values kept are capped at 16 MiB. Keys now match exactly rather than case-insensitively. The other hosts still hold the body (ROADMAP 168).
- Docker: private registries. `RIPPLE_REGISTRY_AUTH_FILE` points at a Docker `config.json` (`auths` with `auth` or `username`/`password`); `registry.Client.Auth` (new `registry.Credentials`, `LoadDockerConfig`, `ParseDockerConfig`) answers a Basic challenge with the login and presents it to the token endpoint of a Bearer challenge, only for the registry it is saved for; `credsStore`, `credHelpers` and identity tokens are not read and are warned about. Logins redact themselves in logs and never reach a PR. Additive. Covered end to end against the fake GitHub and a fake registry that demands a login (token and Basic modes); never run against a real private registry. See [docs/docker.md](docs/docker.md).
- Docker: a tag's release time is the image config's `created` (new `registry.Client.Created`; the engine reads it through the optional `engine.CreatedRegistry`), so a cooldown counts from when the image was built, not from when ripple first polled it; a missing or failed read falls back to first sight. Additive. Covered end to end with a fake registry serving index, manifest and config blob; never run against a real registry.
- Delivery dedupe: Gerrit and SCM-Manager push events now carry a derived `Delivery` (project, ref and old..new revisions; repo, branch and changeset ids), so the store's persistent delivery table drops a redelivery across restarts and replicas for those hosts as it does for the others. Additive. Verified end to end through `App.Handler` over two replicas on one store, and by a receiver test each.
- DynamoDB: removal tombstones are named `removed#<name>`, an indexed cursor group, so the daily sweep is a Query instead of a filtered Scan of the whole table; `Dynamo.PurgeCursors` queries any prefix that names a group. Tombstones written as `removed|<name>` are still honoured, cleared by a re-add and swept until a full 24 hours after the first sweep, then that Scan stops (`tombstones-legacy` cursor). Verified on memory and the in-process DynamoDB by the store suite and engine/e2e tests; Postgres and DynamoDB Local are CI-only.
- Webhooks: `RIPPLE_WEBHOOK_DEDUPE_SIGNATURE=true` (default off) drops a delivery whose verified signature was already handled in the last hour, on GitHub, Gitea/Forgejo, Bitbucket Cloud and Bitbucket Server, so a captured body replayed under a new delivery id is dropped. `webhook.DefaultDedupeBySignature` and `webhook.SignatureKey` are new (additive); `Handler.DedupeBySignature` is unchanged. A genuine redelivery of an identical body is dropped too, which is why it is opt-in. GitLab (its `webhook-id` is already signed) and CodeCommit (SNS `MessageId`) are unchanged. Verified by a receiver test per host; the table is in memory, so it does not span replicas.
- Docker: `COPY --from=image:tag`, `ARG V=...` used as the whole tag of one image (the ARG line moves), and the `image:` key of Compose files and Kubernetes manifests are read and moved with the same tag, digest and cooldown rules; see [docs/docker.md](docs/docker.md). Additive. Covered end to end against the fake GitHub and the fake registry.
- npm: partial ranges and x-ranges (`1`, `1.2`, `^1.2`, `~1.2`, `1.x`, `1.2.x`) are moved at the precision written, and the watcher offers the newest release of each update type the repo's rules allow, so a repo ignoring majors still gets the minor behind a newer major (before, only the newest release was considered). `manager.ParseNpmRange` and `npmreg.Packument.Releases` are new (additive); `NpmRangeFloor` accepts partial ranges. Verified end to end against the fake registry.
- Cargo: partial requirements (`1`, `1.2`, `^1.2`, `~1.2`, `=0.2`) are moved at the precision written, and an update's type follows cargo's compatibility rule (`^0.2.3` to 0.3.0 and `^0.0.3` to 0.0.4 are "major"). The watcher now offers the newest release of each type that the repo's rules allow, so a repo ignoring majors still gets the patch behind a 0.x minor. `manager.ParseCargoReq` is new (additive); `CargoReqFloor` accepts partial requirements. Behaviour change: 0.x minor bumps were "minor" and are now "major", so an `ignore`/automerge rule on `minor` no longer matches them. Verified end to end against the fake sparse index.
- Replicas: the pip poller is elected like the others (lease `feed:pip`; `PipWatcher.PollElected`, `Elected`, `StepDown`), and `GET /replica` lists `pip` in `pollers`. Additive. Verified on the memory store over two replicas, including `App.Run` over real sockets.
- Package cursors: the polled-package sets are one cursor per package, so replicas no longer lose each other's additions. New optional `store.CursorLister` (`ListCursors(prefix)`, `DeleteCursor`) on memory, Postgres (`starts_with`) and DynamoDB (a cursor named `<group>#<key>` is indexed on gsi1 as `CURSORS#<group>`, so a group lists with one Query; other prefixes scan, as `PurgeCursors` does). `github-tags:packages`, `docker:packages` and `npm:packages` keep a `<cursor>#<package>` cursor per package; the watchers read those and the old newline cursor, which is no longer written, and a store without `CursorLister` keeps the old behaviour. Additive. Verified by a shared store test on the memory store and the in-process DynamoDB, engine tests for the union, legacy and fallback paths, and the actions prune end to end; the Postgres and DynamoDB Local runs are CI-only. See [docs/store-dynamodb.md](docs/store-dynamodb.md).
- Replicas: the toolchain, GitHub Actions, Docker, npm and Cargo pollers are elected like the Go module feed, each on its own `feed:<name>` lease (`feed:go-toolchain`, `feed:github-actions`, `feed:docker`, `feed:npm`, `feed:cargo`); `PollElected`, `Elected` and `StepDown` on each watcher. One replica polls each source and another takes over when its claim lapses or it stops. `GET /replica` gains `pollers` (the sources this replica polls) and `feed_pollers` now counts replicas polling any source. Additive. Verified on the memory store over two replicas, including `App.Run` over real sockets; election on Postgres and DynamoDB is covered by the shared lease suite only.
- pip manager, opt-in `ecosystem: pip` ([docs/pip.md](docs/pip.md)): `requirements*.txt` and `pyproject.toml` (`[project]` dependencies, optional dependencies, dependency groups) requirements with a single `==`, `~=` or `>=` clause on a plain release move to a newer release read anonymously from PyPI's JSON API, ordered by PEP 440 (prereleases, dev and local versions, yanked releases and releases without files are skipped), keeping the operator, extras, markers and the file's layout. Lock files are never regenerated (ripple runs no pip, poetry or uv); the PR body lists those it left stale. Hash-pinned requirements, pip-compile and uv output, and every file whose directory or a parent names another index (`--index-url`, `--extra-index-url`, `pip.conf`, `uv.toml`, a pyproject source) are skipped. New `internal/pypi`, `testutil.PyPI`, vendored excerpt `docs/vendor/pip`, UPSTREAM.md pin. Verified end to end against the fake GitHub and the fake PyPI; never against pypi.org or a real pip run.
- Dependency dashboard: when a repo's config stops parsing, an existing dashboard says so ("Configuration invalid", with the parse error) instead of going stale, and drops the notice when the file is fixed.
- Dependency dashboard: turning `dependency-dashboard` back on reopens the issue ripple closed when it was turned off (new optional `platform.IssueReopener`, implemented by the GitHub host), and still never reopens one a person closed.
- Replicas: `HasOlderEvent` on DynamoDB is now consistent. Every live event has a marker item `REPOEVENTS#<repo>` / `<seq>\x1f<id>`, written in the transaction that enqueues or requeues the event and deleted in the one that dead-letters or deletes it (`EnqueueEvent`, `EnqueueSequenced`, `UpdateEvent*`, `RequeueDeadEvent`, `DeleteEvent*`), and the check is a consistent Query of those, so an older event written a moment ago is no longer missed while `gsi1` lags. Events from before get markers from one backfill on the first check (read from the index; roll every replica to this version first), and a marker an older replica left behind is removed when its event is found gone. No migration, additive. Verified on the in-process DynamoDB with a held index (`dynamofake.HoldIndex`) and the shared store suite; the DynamoDB Local run is CI-only. See [docs/replicas.md](docs/replicas.md).
- One package at two versions in one file is two dependencies on every store. Postgres and DynamoDB kept one row per (package, file), so `actions/checkout@v4` beside `actions/checkout@v5.0.0` in one workflow, two `FROM` lines naming one image, or an npm package in both `dependencies` and `devDependencies` collapsed to one row and only one of them was ever updated; the memory store already kept both. Postgres migration 010 widens the primary key with `version`; DynamoDB gives the second and later versions a `\x1e<version>` sort-key suffix (the lowest keeps the plain key, so existing items stay valid). Additive: the next scan of a repo restores the missing row. Verified by a shared store test on the memory store and the in-process DynamoDB, and end to end for two action tag shapes over the memory store; the Postgres and DynamoDB Local runs are CI-only. See [docs/store-dynamodb.md](docs/store-dynamodb.md).
- Docker and npm PRs say where the version was seen ("a new tag appeared on the registry", "a new version was published to the npm registry") instead of claiming the Go module index; a PR mixing datasources says "upstream".
- Replicas: events are numbered by the store, not by the receiving replica's clock. New optional `store.EventSequencer` (`EnqueueSequenced`; memory counter, Postgres migration 009 `event_seq` bumped inside the insert so number order is commit order, DynamoDB counter item `EVENTSEQ` moved by the same transaction as the event put) and `Queue.Add` uses it when the store has it, so skewed replica clocks no longer reorder two events of a repo. The sequence starts above every earlier `Seq`, which keep their place. Additive. Verified on the memory store and the in-process DynamoDB, and by two queues with clocks an hour apart; the Postgres run is CI-only and DynamoDB contention was not measured. The DynamoDB older-event check is still an eventually consistent index read, see ROADMAP. See [docs/replicas.md](docs/replicas.md).
- Replicas are counted: each replica beats on its own store row every third of the lease TTL (new optional `store.ReplicaTable`: `Heartbeat`, `LiveReplicas`, `RetireReplica`; memory, Postgres migration 008 `replicas`, DynamoDB items `PK=REPLICAS`), the row lapses after one TTL and is removed on a clean stop. `GET /replica` gains `replicas_live`, `feed_pollers` and `lease_takeovers_all_replicas`. Additive. Verified on the memory store, the in-process DynamoDB and two `App.Run` replicas over real sockets; the Postgres run is CI-only and nothing ran against real DynamoDB. See [docs/replicas.md](docs/replicas.md).
- Partial scan on hosts that serve only part of it: a checkout whose filtered clone cannot fetch its omitted blobs by object id (a host on git protocol v0 without `uploadpack.allowAnySHA1InWant`) now repeats once as an unfiltered clone, so the full-checkout fallback of a scan no longer fails on such a host and leaves the repo unscanned. Test-only helpers `GitHub.SetPartialClone` and `GitHTTP.SpeakProtocolV0`; `TestScanOnHostsWithPartialCapabilities` covers both half-way hosts. Verified against the fake over git-http-backend only; no real GitLab, Gitea, Bitbucket, Azure, Gerrit or CodeCommit was cloned from. See [docs/bounds.md](docs/bounds.md).
- GitHub Actions residuals: a newer tag now closes ripple's stale open PR for the same action and tag shape (the Go supersede sweep, `close-superseded-pull-requests`), and an action whose shape has no newer tag (`v4` with only `v5.0.0` upstream) is listed on the dependency dashboard under "Actions left alone". On GHES, `RIPPLE_ACTIONS_UPSTREAM_URL` (and optional `RIPPLE_ACTIONS_UPSTREAM_TOKEN`, never sent the installation token) names a host to read an action's tags from when the GHES host lacks the repository. Actions nobody uses any more leave the polled set, and actions PRs no longer say "module index". Additive. Verified end to end against the fake GitHub and fake GHES on every store; never against github.com or a real GHES. See [docs/github-actions.md](docs/github-actions.md).
- `RIPPLE_CONTAINER_CONFINE=true` (docker and podman, default off) starts the confined container network at server start (internal network plus an nginx proxy sidecar from `sandbox.ConfineNetwork`), points the commands' `GOPROXY` at it while the server keeps using `RIPPLE_GOPROXY` itself, removes a confinement a killed server left behind, and removes it on a normal stop (`App.Close`). New `sandbox.ContainerOptions.ProxyURL`, `sandbox.ClientEnver`, `sandbox.RemoveConfinement`; refused with `RIPPLE_GOPROXY_TOKEN`, `RIPPLE_CONTAINER_NETWORK` or a proxy URL with a path. The container client is now started with its own `HOME` and runtime variables rather than the job's, so rootless Podman no longer keeps its image storage in the job directory (the job's `HOME` and `TMPDIR` reach the container as `-e HOME=<dir>`). `docker/runner/Dockerfile` is the runner image (git and a pinned Go, `GOTOOLCHAIN=local`). The `container-runtimes` CI job now builds it, runs local git and the server's wiring against real Docker and Podman; nothing here ran locally except the Apple path and the unit tests. Additive. See [docs/sandbox.md](docs/sandbox.md).
- Replicas: the remaining writes are fenced on their lease. New `Store` methods `SetCursorFenced`, `UpdateEventFenced` and `DeleteEventFenced` (memory: one critical section; Postgres: one statement with `EXISTS` on the lease row; DynamoDB: a transaction with a condition check on the lease item) refuse a replica whose lease was lost with `ErrLeaseLost`. The engine uses them for the advisory pass's job advance and the cursors of pause, resume, remove and rename; the queue for an event's retry, dead-letter and delete. One replica polls the Go module feed (`Watcher.PollElected`, lease `feed:<name>`; the other pollers are not elected yet). New `GET /replica` reports the replica name, whether it is the feed poller and `store.LeaseTakeovers()`, since there is no metrics surface; a live replica count is not available. No migration. Verified end to end on two replicas over the memory store and the in-process DynamoDB; the Postgres and DynamoDB Local runs are CI-only. See [docs/replicas.md](docs/replicas.md).
- DynamoDB hygiene: `ripple dynamodb check-counts`, `recount` and `backfill-failed-jobs` (`Dynamo.CheckDependentCounts`, `RecountAllDependents`, `BackfillFailedJobs`, `CountDrift`; additive) check or repair every package's dependents counter and write the open-job copies of failed jobs from before the copies existed, none of them run by the server; the counters now keep following writes after the option was turned off again. `dynamofake` rejects the full vendored reserved-word list and an empty key value or sort-key bound, as DynamoDB Local does, and the parity script's self-test covers a skipped Local run. The e2e `waitRepo` now waits for the first scan to end (`waitRegistered` for held-checkout tests), so install is deterministic. The Scan paths and the Local rejection of empty keys are only exercised by the fake locally; the DynamoDB Local runs are CI-only and nothing ran against real AWS. See [docs/store-dynamodb.md](docs/store-dynamodb.md).
- Cargo manager, opt-in `ecosystem: cargo` ([docs/cargo.md](docs/cargo.md)): `Cargo.toml` dependency requirements (`[dependencies]`, dev, build, target and workspace tables; inline and named tables; `package` renames) with a full `x.y.z` requirement (bare, `=`, `^`, `~`) move to a newer release read anonymously from crates.io's sparse index (prereleases and yanked versions are skipped), keeping the operator and the file's layout. `Cargo.lock` is left untouched (ripple runs no cargo) and the PR body lists the locks it left stale, including a workspace root's. Path, git and other-registry dependencies, and repos whose `.cargo/config.toml` has `replace-with`, are skipped. New `internal/cratesindex`, `testutil.CratesIndex`, vendored excerpt `docs/vendor/cargo`, UPSTREAM.md pin. Verified end to end against the fake GitHub and the fake index; never against index.crates.io or a real cargo run.
- npm manager, opt-in `ecosystem: npm` ([docs/npm.md](docs/npm.md)): `package.json` dependencies, devDependencies and optionalDependencies with a full `x.y.z` range (bare, `=`, `^`, `~`) move to a newer release read anonymously from registry.npmjs.org (abbreviated metadata; prereleases, deprecated versions and versions above the `latest` dist-tag are skipped), keeping the operator and the file's layout. Lockfiles are never regenerated (ripple runs no npm); the PR body lists those it left stale. A package whose `.npmrc` names another registry is skipped. New `internal/npmreg`, `testutil.NpmRegistry`, vendored excerpt `docs/vendor/npm`, UPSTREAM.md pin. Verified end to end against the fake GitHub and the fake registry; never against registry.npmjs.org or a real npm run.
- The Docker and Podman runners are now verified against real daemons: a `container-runtimes` CI job (hosted Linux runner) runs the live test the Apple runner has (build, `go mod tidy`, read-only root, writable mounts, no network without a proxy, no host files, timeout reap) under `-tags containerlive`. It found one argv fix: rootless Podman now gets `--userns keep-id`, else `--user` cannot write the bind mounts. New `sandbox.ConfineNetwork` (docker and podman) creates an internal network plus an nginx proxy sidecar that forwards to the module proxy and returns `Confinement{Network, ProxyURL}` for `ContainerOptions.Network` and `GOPROXY`; the same job shows `go mod download` working through it while `1.1.1.1` and `proxy.golang.org` are unreachable from the container. Not yet reachable from the server's settings, see ROADMAP; Apple's `container` has no internal networks and is refused. Only CI ran these, never locally. See [docs/sandbox.md](docs/sandbox.md).
- Superseded pull requests: a stale PR a person touched is remembered per repo (cursor `supersede-touched:<repo>`, forgotten when the PR leaves the open list), so it is no longer re-read (about six requests) on every run of the repo. No `Store` or platform interface change. Verified end to end against the fake GitHub on every store; no real host.
- OSV residuals: the post-gap sweep now covers DynamoDB (`store.Dynamo` implements `store.RepoLister` from a `REPOS` index item written beside each repo, built once by one Scan for tables that predate it; the Scan has never run against DynamoDB Local or AWS outside CI), `RIPPLE_OSV_SWEEP_BATCH` sets the repos per poll, and a repo larger than one history round (`Engine.HistoryQueries`, `HistoryFetch`) is swept over several rounds and polls. A record corrected while its repo was busy is retried on later polls (cursor `osv-reconcile-retry`) instead of waiting for the record to change again. A security toolchain PR now closes an already-open non-security directive or toolchain PR of ripple's (untouched only) and requeues its job behind it. Additive, no migration. Verified end to end against the fake GitHub and fake OSV on the memory store and the in-process DynamoDB; Postgres and DynamoDB Local only in CI. See [docs/osv.md](docs/osv.md).
- Dockerfile manager, opt-in `ecosystem: docker` ([docs/docker.md](docs/docker.md)): `FROM image:tag` (with `--platform` and `AS`) moves to a newer tag of the same shape, and `image:tag@sha256:...` moves tag and digest together, from the Docker Registry HTTP API v2 read anonymously (Docker Hub, GHCR, generic registries; `internal/registry`, `engine.DockerWatcher`, `engine.Engine.Registry`, additive). `FROM golang:` is left to the Go version files; compose files and credentials are not covered. Covered end to end against the fake GitHub and a fake registry (`internal/testutil/registry.go`); never run against a real registry.
- Webhook delivery ids live in the Store: a handled `X-GitHub-Delivery` (and the Bitbucket and Azure ids) is claimed in a shared table, so a restart or a second replica drops a redelivery; a delivery whose queueing fails is released so the retry gets through. `App.DeliveryTTL` (default 1h, negative disables). New optional `store.DeliveryTable` (memory, Postgres migration 007, DynamoDB items `DELIVERY#<id>`), additive. Removal tombstones (`removed|<repo>` cursors) are now swept daily through the optional `store.CursorPurger`; the DynamoDB sweep is a filtered Scan, unmeasured on large tables. Retry-id stability for Bitbucket Cloud and Azure DevOps is documented as unverified (the vendored docs do not say) and left on ROADMAP. Covered end to end on the memory store and in-process DynamoDB; the Postgres and DynamoDB Local runs are CI-only.
- Dependency dashboard bookkeeping: the set of repos to refresh after a feed poll is kept in the store (cursor `dashboard-dirty`), so a restart no longer drops it; an unchanged dashboard is read back about hourly and rewritten if a person edited it (the cursor gains a checked time; old cursors are read back once); turning `dependency-dashboard` off closes the issue once; a repo whose issues are unavailable is left alone for an hour across restarts (cursor `dashboard-off:<repo>`). New optional `platform.IssueCloser` (GitHub implements it; `platform.CloseIssue`, `Mux` and the counting test platform forward it), `testutil.GitHub.IssueRequests` and `HumanEditIssue`. No store interface change. Covered end to end against the fake GitHub on the memory store; the Postgres and DynamoDB runs are CI-only, and the real GitHub close and edit behaviour is from the docs, not a live App.
- Webhook bodies can stay off the disk: `RIPPLE_WEBHOOK_SPOOL=memory` (`webhook.Guard.Spool`, `webhook.DefaultSpool`; default `disk`, unchanged) holds a signed body over 64 KiB in memory while its signature is checked instead of spilling it to a temp file, for a read-only root or a small temp dir. The cost of a forged body moves from disk to memory (up to 4 x the 25 MB cap). The server's read deadlines (header 10s, request 1m, write 1m) are now idle-bounded too (`IdleTimeout` 2m) and tested against a stalled client.
- Dead letters, failed jobs: `ripple events jobs REPO` lists a repo's failed jobs with their keys and `ripple events requeue-job KEY` puts one back to pending with a fresh attempt budget; a running server runs it on its next job poll. No metric was added: the service has no metrics surface yet.
- DynamoDB residuals: open-job copies are backfilled from the pending index on every start and reconciled on read (a stale or orphaned copy no longer shows on a dashboard); `Dynamo.RecountDependents` recounts a package's adaptive counter from the index, raises its shard count and moves dependents to their hashed shard, and the first change to a package with no counter item does the same; `RIPPLE_DYNAMODB_COUNTER_STRIPES` (default 1) spreads the counter over several items (`WithCounterStripes`); `dynamofake` gains BatchGetItem, Scan, `UPDATED_OLD`, a reserved-word check, a held-index mode and throttling hooks, and CI diffs the fake's results against DynamoDB Local's (`scripts/check-dynamo-parity.sh`). ### Fixed
- Feed poll: a poll no longer waits for a repo a job is running. The poll ends by syncing dashboards, which took each marked repo's in-process lock, so a poll that enqueued a job for a repo whose run began before the sync (a slow checkout) stalled, and every later poll with it, until that job ended; the repo is now skipped and stays marked for the next flush, as a repo another replica holds already was. Showed up as an intermittent `TestSlowJobDoesNotStallFeedPoll/dynamodb` timeout in CI. Verified by an engine test; the DynamoDB Local run is CI-only.
- A failed event's retry could lose its lease to the previous attempt's release: the queue made the event runnable again before releasing its lease, the retry re-took the same owner's lease with the same token, and the late release deleted it, so the retry's outcome was refused as lost, its attempt not counted, and the event rescanned more than `MaxAttempts` times (seen as `TestDeadLetterThenRequeue/postgres`: 5 scans, want 3). The lease is now released before the event is queued again. Reproduced on the memory store with a slow release; the Postgres run is CI-only.
- Container backends: a command that timed out left its container behind, stopped, about half the time under Apple's CLI (`--rm` is the killed client's job); the reaper now always removes it. The live test checks only its own container and reports debris from other runs.
- CI: the `test` job piped `go test` into `tee` without `pipefail`, so failing tests never turned it red; it now runs with `set -o pipefail`. Data race fixed: a webhook delivery read `Queue.Now` (`App.nowTime`, from `claimDelivery`) while `Queue.Run` filled in the queue defaults; `nowTime` now goes through the idempotent, mutex-guarded `Queue.init`. Regression test `TestDeliveryWhileQueueStartsDoesNotRace`.

### Security
- OS-level sandbox for `go` and local `git` (`RIPPLE_SANDBOX`: `none` (default), `auto`, `seatbelt`, `bwrap`).
  Under `seatbelt` (macOS) the commands run with every path unreadable and unwritable except the
  checkout, the build cache and the toolchain, and the only network they can open is a loopback gate
  to `RIPPLE_GOPROXY` behind a random path prefix. `bwrap` (Linux) is implemented but unverified and cannot
  confine the network to a proxy, so `go` refuses to run under it. Clone, fetch and push are not
  confined. See [docs/sandbox.md](docs/sandbox.md).
- Webhook receiver: requests without a well-formed `X-Hub-Signature-256` are refused before the body is
  read, at most 4 bodies are buffered at once (others get 503 with `Retry-After`), and a declared length
  over the limit gets 413. A repeated `X-GitHub-Delivery` within an hour is acknowledged and dropped, so a
  replayed signed event is handled once; a delivery that failed with 503 can still be redelivered.
  `webhook.Handler` gains optional `MaxBody`, `MaxInflight`, `DedupeTTL` and `Now` fields; zero values keep safe defaults.

  docs/bounds.md).
- Fan-out loads and parses a repo's config once per release instead of once per dependency row.

- `RIPPLE_MAX_FILES` (default 100000) and `RIPPLE_MAX_DEPENDENCIES` (default 5000) cap one repo scan; a repo
  over a cap is skipped with a logged warning and no updates until it is under it
  ([docs/bounds.md](docs/bounds.md)).

## [0.2.0] - 2026-11-22

### Added
- `.ripple.yaml` (repository root, the same on every host) is the per-repo configuration file;
  `ripple config validate` checks it by default.

### Deprecated
- `.github/ripple.yml`, the path v0.1.0 read, is a deprecated alias for `.ripple.yaml` with identical
  meaning. When both exist `.ripple.yaml` wins, the alias is ignored, and a warning is logged and shown
  by `ripple config validate`. Removal no earlier than v0.3.0.

### Documentation
- ROADMAP entries for every Renovate code host, container job runners with updaters as OCI images,
  a prebuilt image and binaries, and hermetic integration tests.

## [0.1.0] - 2026-11-22

### Added
- `ripple version` prints the module version the binary was built from.
- Event-driven updater: polls the Go module index once, finds importing repositories through a
  reverse index, and opens pull requests only there.
- `.github/ripple.yml` per-repo configuration with strict validation; `ripple config validate`.
- Managers: `gomod` and a generic `regex` manager.
- Stores: Postgres and DynamoDB (single table, documented GSI), plus an in-memory store.
- minimumReleaseAge, grouping, per-rule automerge, schedule windows and an open-PR limit.
- GitHub App webhook receiver and `ripple serve`; Dockerfile.
- Go major-version updates: the reverse index keys on the module line, so `/vN` to `/vN+1`, an
  unsuffixed path to `/v2` and `gopkg.in/x.v2` to `.v3` are found; `go.mod` and all import paths are
  rewritten with `go/parser`, verified with `go mod tidy`, `go build` and `go vet`, opened as a
  labelled `[major]` PR (a draft with the compiler output if verification fails), never auto-merged
  unless the repo file says `automerge: major`. New server setting `RIPPLE_GOPROXY`.

### Security
- `go` is no longer run in a checkout containing a symlinked `go.mod`, `go.sum`, `go.work` or `.go`
  file, or a `replace` to an absolute or out-of-repository path; the job fails permanently, no PR.

### Fixed
- The regex manager replaced only some matches when several patterns matched out of offset order;
  matches are now sorted, and overlapping ones are rejected.
- A major bump no longer fails because one `.go` file does not parse (it is listed in the PR body),
  and no longer rewrites `testdata/` or directories starting with `_` or `.`.
- Corrected the `webhook.Sink` comment: GitHub does not redeliver a failed webhook by itself.

### Documentation
- README section "Known limitations and security model"; ROADMAP entries for an OS sandbox,
  durable per-installation queues, scan bounds, webhook body bounds, per-command tokens and delivery dedupe.
