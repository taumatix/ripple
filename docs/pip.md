# pip manager

Opt in per repo in `.ripple.yaml`:

```yaml
updates:
  - ecosystem: pip
    directory: /          # optional; default /
```

Only `directory` applies (and the shared keys such as cooldown and grouping). Without the entry ripple does not read
Python files. Paths under `node_modules`, `venv`, `.venv`, `.tox` and `site-packages` are never read.

## What is read and moved

- `requirements*.txt`, `requirements*.in`, `constraints*.txt`/`.in` (and `*.txt`/`*.in` in a directory named
  `requirements`): one requirement per line.
- `pyproject.toml`: the `[project] dependencies` array, every array of `[project.optional-dependencies]` and every array
  of `[dependency-groups]`, `[build-system] requires` (strings only; `{include-group = ...}` entries are skipped), and
  Poetry's `[tool.poetry.dependencies]`, `dev-dependencies` and `group.<name>.dependencies` tables (also
  `[tool.poetry.dependencies.<name>]` with a `version` key). `python` is not a dependency.
- `Pipfile`: `[packages]` and `[dev-packages]`.

| Specifier | Handling |
|---|---|
| `==2.31.0`, `~=8.1.0`, `>=8.0` (one clause, a plain release of 1 to 4 numbers; `~=` needs 2) | moved to a newer release; the operator is kept |
| `>=1.20,<2` (a `>=` floor with `<`, `<=` and `!=` clauses, in any order) | the floor moves to the newest release the other clauses allow; they are never edited, so `2.0` is not a target of `>=1.20,<2` |
| Poetry `^2.31`, `~2.31`, bare `2.31.0`; inline `{ version = "^2.31", extras = [...] }` | moved like `>=`: the newest release above the version, the operator kept (`^2.31` to `^3.0` when 3.0 is out) |
| `==1.*`, `===`, `!=`, `<`, `<=`, `>`, a range without a `>=` floor or with a second `==`/`~=`, prereleases, Poetry `*`, multiple-constraint arrays, `path`/`git`/`url` dependencies, a bare name | ignored: not a requirement ripple reads with certainty |
| `name @ url`, `-e`, `-r`, `-c` and other option lines | ignored |
| a requirement with `--hash` | ignored: bumping it would leave a stale hash |
| a requirements file whose header says `autogenerated by pip-compile` or `autogenerated by uv` | not read: it is a lock file |

Extras and environment markers (`name[extra]==1.0 ; python_version >= "3.9"`) are kept. Names are matched by PEP 503
normalization (`Flask_Login` and `flask-login` are one project). Only the version number is edited; layout, comments and
order are kept byte for byte, and every place the same project and specifier appears in a file moves together. One
project moves per PR, on branch `ripple/pip/<project>-<version>`. Update types follow the first three release numbers
(`2.31` to `2.32` is minor, `2.31.0.1` to `2.31.0.2` patch), so `ignore` and automerge rules apply as for Go modules.

A `>=` floor is raised on every new release, as a Cargo `^` requirement is: that is the only change a PR can carry. Use
`ignore` or a cooldown if that is too many PRs. `setup.py`, `setup.cfg` and `Pipfile.lock`-style files are not read.

## Which version

Read anonymously from PyPI's JSON API (`GET /pypi/<normalized name>/json`, `releases`). The target is the newest version
above the specifier's version, ordered by PEP 440, that is a final or post release (no `a`, `b`, `rc`, `.dev` or `+local`
version), has at least one file and is not yanked (a release is yanked when every file is). The API's upload times are
not read, so the cooldown runs from when ripple first saw the version. Only projects some repo uses are read, once per
poll, never the index as a whole.

Ordering and specifier matching are checked against the `packaging` library on a recorded vector table
(`internal/pypi/testdata/pep440.json`, regenerated by `scripts/gen-pep440-vectors.py`).

`Requires-Python` is not read: a new release may need a newer interpreter than the repo runs.

## Lock files

ripple never runs pip, poetry, uv or pdm. **Lock files are left exactly as they were.** A `requirements.in` that moves also reports the `requirements.txt` beside it when that is a pip-compile output. When `poetry.lock`, `uv.lock`,
`pdm.lock`, `Pipfile.lock` or `pylock.toml` sits beside an edited file or in a parent directory, the PR body lists it
under "Lock files not regenerated": the owner re-locks before merging.

## Private indexes

The client never sends a credential. A project that answers 401, 403 or 404 is logged and left alone. A dependency is
skipped, and its job recorded as skipped with the reason, when its own file, or `requirements.txt`, `pyproject.toml`, `Pipfile`,
`pip.conf`, `pip.ini` or `uv.toml` in its directory or a parent, names another index: `-i`/`--index-url`,
`--extra-index-url`, `-f`/`--find-links`, `--no-index`, a `[[source]]` in a Pipfile other than pypi.org, a `[[tool.poetry.source]]`, `[[tool.uv.index]]` or
`[[tool.pdm.source]]` table, or an `index-url` key. A PyPI project of the same name could be a different package from
the one the repo installs (dependency confusion), so ripple does not guess. This is conservative: a file that names
`https://pypi.org/simple` explicitly is skipped too. `PIP_INDEX_URL` and user-level `pip.conf` are not visible to ripple.
